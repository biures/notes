# Handoff workflow: Opus writes the spec, Sonnet implements, Opus verifies

Two Claude Code skills that keep the expensive model for judgment only. `handoff-spec` and `handoff-implement` are the other two notes of today; this one is how to install and run them, and why the result holds up against an end-to-end Opus run.

## Install (once, per machine)

```sh
mkdir -p ~/.claude/skills/handoff-spec ~/.claude/skills/handoff-implement
# paste each SKILL.md from the two companion notes into:
#   ~/.claude/skills/handoff-spec/SKILL.md
#   ~/.claude/skills/handoff-implement/SKILL.md
```

Project-local works too (`.claude/skills/<name>/SKILL.md` in the repo), which is the better place at work so the whole team gets them.

Each skill pins its own model in the frontmatter (`model: opus` for the spec, `model: sonnet` for the implementer), so you do not touch `/model` during the loop. The pin applies while that skill is active, then the session returns to whatever model it was on. Source: Claude Code docs, skills page, `model` field ("accepts the same values as /model, or inherit").

## The loop

```
/handoff-spec <task, ticket text, or "see JIRA-123">      # Opus: investigates, decides, writes specs/<slug>.md
/handoff-implement specs/<slug>.md                       # Sonnet: executes, verifies each step, reports
/handoff-spec verify specs/<slug>.md                     # Opus: diff + report against the spec → PASS or a fix list
/handoff-implement specs/<slug>.md --fixes               # Sonnet: runs the fix list the same way
```

Run the verify step after `/compact`, or in a fresh session, when the implementation turn was long. Verify mode needs only the spec, the report and `git diff`, so the Opus input stays small.

Decision rule for which tasks to hand off: if you can write "done" as commands with expected outputs before starting, hand it off. If the design will only emerge while coding (exploration, unclear requirements, a spike), use Opus end to end; a spec written without the answers would move the guessing to the weaker model, which is the one thing this loop exists to prevent.

## Why the result matches an end-to-end Opus run

The cheaper model diverges in five known ways. Each one has a counter built into the prompts:

1. **It guesses at ambiguity.** The spec forbids every open decision: names, shapes, defaults, failure behaviour are all decided by Opus, and the spec skill greps its own output for hedge words before handing off.
2. **It writes weaker code where the problem is hard.** Opus writes the risky code verbatim into the spec. The implementer places it; it does not author it.
3. **It drifts: refactors "while here", touches extra files, adds a dependency.** The implementer has an explicit forbidden-moves list and a files-to-touch list; verify mode fails the diff on anything outside it.
4. **It declares done without proof, or makes a check pass by weakening it.** Every step carries a Verify command with an exact expected result; a red step stops the run; deleting or weakening a test is forbidden by name; verify mode re-runs the acceptance commands itself.
5. **It works around a mismatch instead of reporting it.** Any disagreement between spec and reality is a Deviation report and a stop, except a fallback Opus pre-authorized in that step.

What this does not cover: a wrong decision by Opus in the spec is reproduced faithfully by the implementer. That is the same risk as the end-to-end run, and verify mode's last check ("does the code do what the spec says, not merely pass") is where it surfaces.

## Cost shape

Opus pays for the investigation, the spec and the verify pass. Sonnet pays for the implementation turns, which are most of the output tokens and all of the tool churn. Measure it with `/cost` on three real tasks before trusting any ratio; the share depends on how much of the task is thinking versus typing.

## Optional: run the implementer as a subagent

If you prefer the Opus session not to carry the implementation transcript at all, add `.claude/agents/handoff-implementer.md`:

```markdown
---
name: handoff-implementer
description: Executes a /handoff-spec spec literally and verifiably; returns the Report back section only.
model: sonnet
tools: Read, Edit, Write, Bash, Grep, Glob
---
Follow ~/.claude/skills/handoff-implement/SKILL.md exactly for the spec path you are given. Return only the filled "Report back" section.
```

Then, from the Opus session: `@"handoff-implementer (agent)" implement specs/<slug>.md`. The subagent's `model: sonnet` wins over the session model (precedence per the sub-agents docs: per-call parameter, then the agent file, then `CLAUDE_CODE_SUBAGENT_MODEL`, then the main model). Keep the slash-skill form for the first few runs so you can watch a Sonnet implementation behave before you stop watching.
